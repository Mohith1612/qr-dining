About the live data. Each primary branch was seeded with an active session (+confirmed order +pending assistance) on T1 and a payment_pending session (+payment awaiting staff confirmation) on T2 — so kitchen/waiter/guest dashboards are populated immediately. The active T1 sessions follow the normal lifecycle: with no live presence they drift to awaiting_reactivation within ~1 min and abandoned a few minutes later (this is correct, and itself testable). The payment_pending sessions are protected from abandonment and persist indefinitely — which is why Saffron Bandra's tables are still occupied weeks later (see the baseline banner at the top). That is correct behaviour, not a defect: a table awaiting settlement must never be auto-abandoned. Re-run --reset to refresh.

The three-way pivot — audit → trace → logs

With no X-Correlation-ID header, audit_log.correlation_id is the trace id:
docker exec manual-testing-postgres psql -U mtest -d qrdining_mtest \
  -c "select action, actor_type, result, correlation_id
      from audit_log order by id desc limit 5;"

# paste correlation_id into SigNoz, then:
grep <correlation_id> /tmp/qrapp-mtest-1.log
Restarting with tracing on — the up-script does not set the OTel vars:
pkill -f '^/tmp/qrapp-mtest$'  then  /tmp/start-mtest-otel.sh
Note the regex anchors — a bare pkill -f qrapp-mtest also matches (and kills) your own shell.

Recommended Testing Order

  1. Guest happy path (Frontend A) — scan a Saffron House table → create session → menu → shared cart → host places order → live order tracking.
  2. Kitchen + waiter loop — advance the order through the KDS, then serve it from the waiter ready queue.
  3. Payment settlement — host initiates cash/UPI → waiter settles → guest sees completion → session closes.
  4. Reconnect & realtime — reload mid-session; idle into awaiting_reactivation and recover; toggle menu availability live.
  5. Multi-instance fan-out (two browsers) — guest on A (:3000/app-1), staff on B (:3001/app-2); confirm events cross instances both ways.
  6. Manager / owner admin — menu, staff, tables, promos, customers, analytics, audit.
  7. Platform + support + billing — org/branch/plan/entitlement/subscription/billing/flags/themes/collateral; support console read-only; sub-role separation; MFA enroll.
  8. Cross-tenant isolation — confirm Saffron tokens/branches/analytics never expose Copper Pot or Urban Brew data (incl. snapshot scoping).
  9. Security — trust-domain rejection, token tampering, lockout, rate limits, server-side host gating, body-size limit.
  10. Pilot-finding regressions — F-8 (session_token never leaked), F-6 (live tracker), F-1 (reconnect reactivation).

Redesign + Phase 0 — What to Verify

Heads-up on the older docs. The User Guide, Session Guide, how-to-use and Checklist were written before the UI redesign, so some screen labels/flows and a few PINs are out of date (e.g. "View cart" → "View Order", "Confirm your order" → "Place order", "Itemized bill" → "Total due"; staff PINs are 1111/2222/3333/4444 as on this page). This dashboard + the list below are authoritative for the current build.

Guest — Serene redesign

  • Welcome: View Menu + Today's Specials carousel + Currently Popular; glass bottom nav.
  • Menu → item sheet (qty, modifiers, note); single-select modifier = radio (server rejects 2 → MODIFIER_CONFLICT).
  • Cart "Review order" → Place order; track = node stepper.
  • Bill = Total due hero + promo entry at the bill (phone prompt) + Pay; opt-in only when branch enables customer-memory.
  • No "are you still here?" churn on an idle tab (presence heartbeat).
  • Stale tab on a closed session → "Your session has ended" (not reconnect loop).

Staff — Ops redesign

  • Ops dark theme persists across refresh (no reset-to-dark) — the original bug.
  • Kitchen KDS shows order items (qty×name, mods, note) + overdue ring.
  • Staff tab: roster + Reset PIN (mgr→waiter/kitchen, owner→anyone), create = owner-only; toolbar Change PIN.
  • Plan tab loads (no "tenant slug" error); Settings has a customer-memory toggle.
  • Menu item: image upload (edit mode) + manual-URL fallback; inline modifier edit.
  • Collateral: Print View == exported PNG/SVG/PDF (design no longer lost); QR points at the frontend, not :8090.

Platform — Ops redesign

  • Near-black + electric-purple chrome; sidebar + toolbar.
  • Analytics → Staff Performance tab (org→branch picker).
  • Themes → actionable custom-token UX (preset swatches + "Open entitlements"); custom tokens gated by custom.theme.
  • Cross-instance: guest on Frontend A (:3000/app-1) + staff on Frontend B (:3001/app-2) → realtime crosses both ways.

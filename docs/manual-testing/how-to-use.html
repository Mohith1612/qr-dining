Section 2

Starting the Stack

Step 1 — Start the database and Redis

Postgres and Redis run inside Docker. Only these two need Docker; the app and frontend run natively.

# From the project root
docker compose up -d postgres redis

# Verify both are healthy
docker compose ps

Both containers should show healthy status within ~15 seconds.

Step 2 — Start the backend API server

The backend reads environment variables from the root .env file. Migrations run automatically on startup.

# Open a dedicated terminal tab for the backend
cd backend
go run ./cmd/server

You should see log lines like:

INF  postgres connected   service=qr-dining
INF  migrations applied   service=qr-dining
INF  redis connected      service=qr-dining
[GIN-debug] Listening on :8080
✓
Confirm the backend is alive: curl http://localhost:8080/health should return {"status":"ok"}

Step 3 — Start the frontend

Open a second terminal tab:

# From project root
cd frontend
npm run dev

Next.js will print the local URL — usually http://localhost:3000. If port 3000 is taken it increments automatically (3001, 3002, …). Watch the terminal output for the actual port.

⚠
Two terminals needed. The backend and frontend must stay running in their own terminal tabs for the duration of testing. Closing either one breaks the app.

Stopping everything

# Stop frontend: Ctrl+C in its terminal
# Stop backend: Ctrl+C in its terminal

# Stop Docker containers (data is preserved in Docker volumes)
docker compose down

Section 4

Guest Flow Guest

Guests access the app by scanning a QR code that encodes the table token URL. For testing, navigate directly in your browser.

1. Join a session at Table T1

Open this URL in your browser (replace the port if your frontend is not on 3000):

http://localhost:3000/table/34832018ce6109e6f0d67063793ae7e2ad6107a52a2368113284a2517e925990

What you see:

  • Table label (T1) and restaurant name
  • Name entry field — enter any name (e.g. "Arjun")
  • Status indicator: "Live · starting a new session" or "Live · X people here"

Enter a name and tap Take your seat →. You are redirected to the session hub at /session/[id].

2. Session Hub

The hub is the home page of the dining session. From here guests navigate to all other pages.

  • View Menu — browse and order food
  • Orders — track live order status from the kitchen
  • Need Help — call a waiter or request the bill
  • Pay Bill — view itemized bill and pay

A dining party card shows all guests seated at the table with a live "in sync" WebSocket indicator.

3. Menu Page

Navigate via the bottom nav or directly: /session/[id]/menu

  • Category tabs — tap Starters, Mains, Breads, Beverages, Desserts to jump to that section (sticky header highlights the active category as you scroll)
  • Dietary filter chips — filter by Veg, Vegan, Non-Veg, Jain, Egg, Chef Special, Bestseller, New, 🌶 / 🌶🌶 / 🌶🌶🌶
  • Search — tap the 🔍 icon to open the search bar; type to filter live across all dishes
  • Item sheet — tap any dish row to open a bottom sheet with price, description, modifiers (e.g. Extra Sauce +₹20 on Paneer Tikka), quantity stepper, and special note field
  • Add to order — adds the item to your cart; a "View cart" bar appears at the bottom showing item count and subtotal

4. Cart & Order Confirmation

Tap the cart bar → /session/[id]/cart

  • Shows all items with quantities and individual prices
  • Promo code field — enter a promo code and Apply to get a discount
  • Shows subtotal summary
  • Tap Confirm your order · ₹X to send the order to the kitchen → redirected to Orders page
✓
Each order gets a human-readable order number like #OR1001 (prefix OR + 4-digit sequence, resets daily). The kitchen and waiter see the same number.

5. Orders Page

/session/[id]/orders

  • Live WebSocket updates — no manual refresh needed
  • Shows order number, timestamp, and a progress pipeline:
StatusMeaning
SENT → PENDINGOrder received by kitchen, awaiting confirmation
CONFIRMEDKitchen acknowledged the order
PREPARINGCooking in progress
READYDish is ready to be served
SERVEDDelivered to the table

6. Help / Assistance Page

/session/[id]/assist

  • Request a waiter — "A host will be with you shortly" / shows pending request card
  • Request the bill — "Ready to pay? We'll bring the bill right over"

Both buttons disable after tapping (prevents duplicate requests). Requests show up immediately on the Waiter dashboard.

7. Payment / Bill Page

/session/[id]/payment

  • Itemized bill — lists every order by number (#OR1001, #OR1002, …) with items and prices
  • Running total
  • Three payment methods:
MethodFlow
💵 CashConfirm → shows "A host will collect at the table"
💳 CardConfirm → shows "Our team is bringing a card terminal"
📱 UPIConfirm → shows "Awaiting confirmation of your UPI transfer"

After payment is initiated, the bill page shows a confirmation state with the paid amount.

Testing multiple guests at the same table

Open the same table URL in two browser tabs with different names. Both guests share the same session. Orders placed by either guest appear on the shared Orders page and on the Kitchen KDS.

Section 5

Staff Login & Role Setup

All staff log in at: http://localhost:3000/staff/login

Enter the Branch ID and PIN. The system returns the first matching staff member (ordered alphabetically by name).

The PIN collision problem

Out of the box, all three staff on Branch 4 have the same PIN 1234. The auth system returns the first alphabetical match:

OrderNameRole returned for PIN 1234
1st (C)Chef Jordankitchen ← wins by default
2nd (O)Owner Samnever reached
3rd (W)Waiter Alexnever reached

To test each role independently, assign each staff member a unique PIN. Do this via the API once both backend and frontend are running:

One-time PIN setup (run in a terminal)

Step A — Log in as kitchen (the default), capture the token:

# Returns Chef Jordan (kitchen) — the default with PIN 1234
KITCHEN_TOKEN=$(curl -s -X POST http://localhost:8080/staff/auth \
  -H "Content-Type: application/json" \
  -d '{"branch_id": 4, "pin": "1234"}' | \
  python3 -c "import sys,json; print(json.load(sys.stdin)['token'])")

echo "Kitchen token: $KITCHEN_TOKEN"

Step B — Change Chef Jordan's (kitchen) PIN to 9999 (each staff can change their own PIN):

curl -s -X PATCH http://localhost:8080/staff/12/pin \
  -H "Authorization: Bearer $KITCHEN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"current_pin": "1234", "new_pin": "9999"}'
# Returns 204 No Content on success

Step C — Now PIN 1234 matches Owner Sam. Log in as owner and capture that token:

OWNER_TOKEN=$(curl -s -X POST http://localhost:8080/staff/auth \
  -H "Content-Type: application/json" \
  -d '{"branch_id": 4, "pin": "1234"}' | \
  python3 -c "import sys,json; print(json.load(sys.stdin)['token'])")

echo "Owner token: $OWNER_TOKEN"

Step D — As owner, change Waiter Alex's PIN to 7777 (owners can change any staff PIN):

curl -s -X PATCH http://localhost:8080/staff/11/pin \
  -H "Authorization: Bearer $OWNER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"current_pin": "1234", "new_pin": "7777"}'

Section 6

Kitchen Role kitchen

URL: http://localhost:3000/staff/kitchen
Login: Branch 4 · PIN 9999 (after PIN setup) or 1234 (before PIN setup)

The kitchen shows a Kanban board with four columns, updated live via WebSocket. Every new order placed by any guest appears here immediately.

The four columns

ColumnAction availableButton label
PENDINGAcknowledge the orderConfirm
CONFIRMEDStart preparingStart cooking
PREPARINGMark as ready for serviceMark ready
READYMark as deliveredServed

What kitchen staff can do

  • View all active orders across all tables in real time
  • Advance any order through the pipeline: Pending → Confirmed → Preparing → Ready → Served
  • See elapsed time per order — cards turn red when an order exceeds 15 minutes
  • See the order number (#OR1001), which matches what the guest sees on their Orders page
  • See summary counts: PENDING / COOKING / ACTIVE

What kitchen staff cannot do

  • Cannot access the admin panel or change menu items
  • Cannot see or act on waiter assistance requests
  • Cannot manage staff accounts or view billing settings

Real-time behaviour

Status changes made here are broadcast over WebSocket to all connected guests. When you click Confirm, the guest's Orders page updates from PENDING to CONFIRMED within a second — no page refresh required.

Section 7

Waiter Role waiter

URL: http://localhost:3000/staff/waiter
Login: Branch 4 · PIN 7777 (after PIN setup)

The waiter dashboard manages the assistance request queue — all calls for help placed by guests from the Help page of their session.

What waiter staff can do

  • See all pending and acknowledged requests across all tables, sorted by urgency
  • See two request types: Waiter needed and Bill request
  • Tap On my way to acknowledge a request (status changes to In Progress)
  • Tap Done (resolve) to close the request
  • See elapsed time — requests that have been waiting over 10 minutes are flagged as URGENT (red border)
  • See a floor plan showing which tables have active requests vs are clear
  • Summary counters: Total / Pending / In Progress

What waiter staff cannot do

  • Cannot access the admin panel
  • Cannot advance kitchen orders
  • Cannot manage staff accounts, menu, or settings

Flow: guest requests → waiter resolves

  1. 1
    Guest opens Help page → taps Request a waiter
  2. 2
    Waiter dashboard shows the request card under NEEDS ATTENTION
  3. 3
    Waiter taps On my way → request moves to acknowledged; guest sees "Someone is on their way"
  4. 4
    After helping the guest, waiter taps Done → request closes

Section 8

Admin / Owner Role owner

URL: http://localhost:3000/staff/admin
Login: Branch 4 · PIN 1234 (after PIN setup, this maps to Owner Sam)

The admin panel has 9 tabs. All staff can view the panel, but write actions (edit, delete, create) are restricted to owner and manager roles. Kitchen and waiter staff see the panel in read-only mode.

Tab 1 — Sessions

  • Lists all active sessions with their table label, session ID, and duration
  • Refresh button to re-fetch
  • (Owner) Close a session manually if needed

Tab 2 — Menu

The full menu CMS. Owners can manage the entire menu from here.

  • Create category — add a new section (e.g. "Chef's Specials")
  • Add item — open a modal form with: name, description, price, dietary flags (Veg/Vegan/Non-Veg/Jain/Egg), badges (Chef Special/Bestseller/New), spice level, featured toggle, image URL
  • Edit item — same modal pre-filled with existing data
  • Delete item — confirmation dialog before removal
  • Toggle availability — mark an item as unavailable (hidden from guest menu) without deleting it; available to all staff roles
  • Add modifiers — create modifier options per item (e.g. "Extra Sauce · +₹20") with required/optional flag
  • Reorder — drag items within a category to change display order

Tab 3 — Tables

  • Lists all tables with their identifier (T1, T2, T3) and QR token
  • (Owner) Refresh QR code — generates a new token, invalidating old links
  • (Owner) Print QR — opens a print-friendly view of the QR code for the table tent

Tab 4 — Staff

  • Lists all staff with name and role
  • (Owner) Add new staff — name, role (owner/waiter/kitchen), initial PIN
  • (Owner) Deactivate staff — immediately invalidates all their login tokens
  • (Owner) Reset PIN for any staff member

Tab 5 — Stats

  • Today's orders — count and total revenue
  • Active sessions count
  • Order breakdown by status
  • Top items by order volume

Tab 6 — Plan

  • Shows the current subscription plan (Free / Pro / Enterprise)
  • Displays feature limits: max tables, max staff, analytics access, promo codes
  • (Owner) Upgrade plan option

Tab 7 — Promos

  • (Owner) Create promo codes — code string, discount amount (fixed ₹) or percentage, validity dates
  • (Owner) Activate / deactivate promos
  • View redemption count per promo

Guests enter promo codes on the Cart page. Valid codes apply the discount to the order total.

Tab 8 — Appearance

  • (Owner) Choose the restaurant's colour theme — applies to the guest-facing menu UI
  • Theme changes are saved and take effect immediately for new guest sessions

Tab 9 — Settings

Billing and session configuration:

  • (Owner) Tax rate — applied to all orders (e.g. 5% GST)
  • (Owner) Service charge rate — added to the bill subtotal
  • (Owner) "Tax inclusive" toggle — whether listed prices already include tax
  • (Owner) Session timeout — idle session auto-close duration (minutes)
  • (Owner) Session warning — how many minutes before expiry to warn guests

Full End-to-End Scenario

Run through this sequence to exercise every part of the system in one pass. You'll need 3 browser windows / tabs:

Window A — Guest (Table T1)

http://localhost:3000/table/34832018ce...

Window B — Kitchen

http://localhost:3000/staff/login → Branch 4, PIN 9999

Window C — Waiter

http://localhost:3000/staff/login → Branch 4, PIN 7777

The scenario

  1. 1
    [Window A] Open the T1 table URL. Enter name "Arjun". Tap Take your seat. You arrive at the session hub.
  2. 2
    [Window A] Tap View Menu. Browse the menu. Tap Paneer Tikka → item sheet opens with the Extra Sauce modifier. Toggle Extra Sauce on. Tap Add to order. Cart bar appears: "1 View cart · ₹200".
  3. 3
    [Window A] Add a second item — e.g. Butter Naan. Cart now shows 2 items.
  4. 4
    [Window A] Tap View cart. On the Cart page, tap Confirm your order. You are redirected to the Orders page showing #OR1001 · PENDING.
  5. 5
    [Window B — Kitchen] Order #OR1001 appears in the PENDING column. Tap Confirm.
  6. 6
    [Window A — Guest] Orders page updates to CONFIRMED — live, no reload needed.
  7. 7
    [Window B — Kitchen] Tap Start cooking → order moves to PREPARING.
  8. 8
    [Window B — Kitchen] Tap Mark ready → order moves to READY.
  9. 9
    [Window B — Kitchen] Tap Served → order is complete.
  10. 10
    [Window A — Guest] Orders page shows SERVED. Tap the bottom nav Help tab → tap Request a waiter.
  11. 11

  12. 12
    [Window A — Guest] Tap Bill in the bottom nav. The itemized bill shows: #OR1001 · Paneer Tikka (+Extra Sauce) · ₹200 and Butter Naan · ₹45. Total: ₹245. Tap Cash to initiate payment.

    [Admin check] Open /staff/admin (Owner Sam, PIN 1234). Go to Sessions tab — the session appears as ACTIVE. Go to Stats tab — today's order count is 1, revenue is ₹245.

Start and stop

Run these commands from the repository root.

Start with fresh data

./scripts/manual-testing-up.sh --reset

--reset removes the manual-testing volumes, migrates, reseeds, builds two backend processes, and starts two frontend processes. The script prints the current staff credentials and QR tokens while seeding. scripts/manual-testing-up.sh:32-75,96-124; backend/scripts/seed.go:769-786

Start without reseeding

./scripts/manual-testing-up.sh

Without --reset, the script starts the datastores and runs migrations but does not execute the seed program. scripts/manual-testing-up.sh:32-53

Use the stack

Open the dashboard. The stack exposes frontends at :3000 and :3001, backends at :8090 and :8095, PostgreSQL at :25432, and Redis at :26379. scripts/manual-testing-up.sh:24-25,62-75,105-123; docker-compose.manual-testing.yml:29-68

The two app processes share the isolated database and Redis. The manual stack explicitly enables centralized authorization enforcement, while the application configuration default is false. scripts/manual-testing-up.sh:24-25,64-75; backend/internal/config/config.go:253-263

Logs

tail -f /tmp/qrapp-mtest-1.log
tail -f /tmp/qrapp-mtest-2.log
tail -f /tmp/frontend-a.log
tail -f /tmp/frontend-b.log

Those are the four output paths configured by the launcher. scripts/manual-testing-up.sh:64-75,105-109,124

Stop

./scripts/manual-testing-down.sh
# or retain the isolated data volumes:
./scripts/manual-testing-down.sh --keep-data

The default removes the manual-testing volumes; --keep-data stops the datastores without deleting those volumes. scripts/manual-testing-down.sh:21-27

The launcher terminates processes matching next dev and listeners on ports 3000/3001. Check those lines before running it on a workstation that has another Next.js development server. scripts/manual-testing-up.sh:88-94; scripts/manual-testing-down.sh:14-19
